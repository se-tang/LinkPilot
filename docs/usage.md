# 使用细节

## 可调参数

发起测试前可自定义下面这些参数，它们直接对应 iperf3 / ping 原生命令：

| 界面项 | 对应参数 | 默认 | 范围 | 说明 |
|:--|:--|:--|:--|:--|
| 线程数 | `iperf3 -P` | 1 | 1–32 | 并行流数；多流才能吃满高带宽链路 |
| 单向时长 | `iperf3 -t` | 10 秒 | 1–300 | 上行、下行各跑一次 |
| 目标机端口 | `iperf3 -p` | 5201 | 1–65535 | 目标机 `iperf3 -s` 监听的端口；**后端机默认也连这个端口** |
| UDP 测试 | `iperf3 -u` | 关 | — | 勾选后按 UDP 发包，报告增加 UDP 丢包 / 抖动两列 |
| UDP 带宽/流 | `iperf3 -b` | 100M | `100M`/`1G`/`500K`（必须带单位） | **按流生效**：`-P 4 -b 100M` 的总目标是 400M |
| ping 次数 | `ping -c` | 200 | 1–2000 | 固定 `-i 1`，所以次数≈秒数 |

### 端口怎么填（两种场景）

| 场景 | 目标机端口 | 各后端机连接端口 |
|:--|:--|:--|
| 普通 / **NAT 机**（商家端口映射基本都是同号映射，如公网 `43343` → 内网 `43343`） | 就填映射的那个端口（如 `43343`） | 不动（默认跟随目标机端口） |
| 目标机有公网 IP，但想让不同后端机走不同端口 | `5201` | 逐台改（如 6001 / 6002） |

- **只改「目标机端口」即可**：后端机没单独改过就自动连这个端口，不用两头都填。
- 目标机会为**目标机端口**以及**每台后端机单独指定过的连接端口**分别起 `iperf3 -s`。
- 某个单独指定的连接端口在目标机本机起不来时只警告不中断，那台后端机会在预检时报明确错误。
- 防火墙/安全组要放行**目标机端口**（NAT 场景即商家控制台里映射/放行的那个端口）；UDP 测试还要放行该端口的 UDP。
- 面板会在开测前对每台机器要用的端口做一次预检，不通会提示并尝试自动重启目标机该端口的 server。

## 一轮测试做什么

1. **目标机**：检查/安装 `iperf3` 与 `ping`，在目标机端口上启动 `iperf3 -s`（后端机单独指定的连接端口也会一并起），并按本轮台数 × 单向时长给 server 设一个**存活上限**（300–3600 秒，只是异常兜底，见「端口与安全组」）；
2. **每台后端机**：环境检查（并行）→ 按参数执行 iperf3 上行 → 下行（`-R`）→ ping；
3. **无论正常结束、手动停止还是出错中断**，都会关闭目标机的 iperf3 server，然后生成报告。

**iperf3 全局串行**（多台同时测速会互相抢带宽，结果作废），**ping 不占测速通道**，与其它机器的 iperf3 并行执行。

总时长 ≈ 1 分钟（环境准备）+ 台数 ×（2 × 单向时长 + 5 秒），ping 与后续机器的 iperf3 重叠进行。

## 测试协议：IPv4 / IPv6

默认 **IPv4**：iperf3 与 ping 都用目标机的 IPv4 地址，两端固定为 IPv4——避免个别机器没有 IPv6 时整轮测试失败。

需要测 IPv6 时勾选「**使用 IPv6 测试（需双端均支持 IPv6）**」（会二次确认）。勾选后改用目标机的 IPv6 地址，**所有选中的后端机器都必须具备 IPv6 连通性**，否则该台失败；面板会在选项旁提示未探测到 IPv6 的后端机器，目标机只有 IPv6 时会自动选中。

## 机器地址怎么来的

无需手填，面板自动采集：

- **心跳观测**：Agent 心跳的来源 IP 按协议族分别记录（双栈面板下 v4/v6 互不覆盖，地址不会在两族之间跳动）；
- **本机探测**：地址不全时，面板通过签名任务让 Agent 在本机执行一次地址探测（`ip route get` / `ip -6 addr`，只做本地查询，不访问外网、不产生流量），因此**面板只监听 IPv4 也能拿到机器的 IPv6**；Agent 无需升级即可支持；
- **展示规则**：机器列表「测试地址」列只显示真正会用于测试的那个地址——双栈机器只显示 IPv4（有没有 IPv6 在后端机器备注里以绿色「有 V6」/ 橙色「无 IPv6」标出），只有 IPv6 的机器才显示 IPv6；「探测地址」按钮可手动刷新（例如机器换 IP 后），探测失败会在地址旁标 ⚠️，鼠标悬停看原因。
- **手动指定**：「添加/编辑机器」里的**手动测试地址**留空即自动；填了就一律按它测（地址旁标「手动」）。NAT 机、或面板前面有 CDN 导致自动采集到的地址不对时用它兜底。

> 探测只接受全局可路由地址（私网、链路本地、ULA 会被忽略）；开启隐私扩展的机器优先取稳定地址，只有临时（temporary）地址的机器会退而使用临时地址，不会因为找不到稳定地址而完全探测不到 IPv6。处于 NAT 后的机器会沿用面板观测到的出口 IP。

## 定时任务（长期对比）

「定时任务」把同一组「目标机 + 后端机」按固定间隔反复测，每轮单独出报告，并额外生成一份**跨轮对比报告**，用来观察线路随时间的变化（晚高峰掉速、丢包变多、路由改动……）。

### 配置项

| 项 | 说明 |
|:--|:--|
| 任务名称 | 只是给人看的标签，随意填 |
| 间隔时间 | 数字 + 单位（分钟 / 小时 / 天），范围 **5 分钟 ~ 30 天** |
| 任务运行时长 | 数字 + 单位（分钟 / 小时 / 天），最长 **365 天**；不勾选「到时自动停止」则一直运行 |
| 目标机器 | 一台角色为「目标机器」的机器（被测端） |
| 后端机器 | 一台或多台角色为「后端机器」的机器（发起端） |
| 自定义测试参数 | 不勾选时**直接跟随「发起测试」区域的当前值**；勾选后可单独设置线程 / 时长 / 端口 / ping / UDP |
| IPv6 | 勾选后按目标机的 IPv6 地址测试（要求所有后端机都具备 IPv6 连通性） |
| 冲突时等待 | 面板正好有测试在跑时的行为：**默认跳过本轮**（推荐，保证对比曲线的时间轴规整）；勾选则改为等它跑完再跑 |

### 执行与排期规则

- **固定间隔**：下一次执行时间 = **上一轮启动时间 + 间隔**，所以某一轮跑得久一点也不会让后面的轮次漂移。
- **保存即启动**：新建定时任务保存后会立即尝试执行首轮；首轮因机器离线、已有测试冲突等原因未跑成时，仍会保留任务并按正常间隔继续。
- **跳过不排队**：默认策略下，如果面板已有测试在跑，这一轮记作「本轮跳过」并写明原因，下一轮按原间隔继续（排队会把后面每一轮都推后，长期对比的时间轴就乱了）。
- **面板重启不丢任务**：排期落库；重启时正在跑的那一轮标记为「已中断」，下一轮照原计划继续。
- **运行时长到期自动停止**：从保存设置时开始计时；当前正在跑的一轮会正常收尾，之后不再触发新轮次。编辑任务并「延长时间」会从当前时刻重新计时并恢复调度。
- **机器离线 / 被删 / 角色改了**：该轮跳过并在面板上写明原因（例如「机器「HK-01」的角色已不是「后端机器」」），不会静默失败。
- **「立即跑一轮」**：手动触发一次，不影响原有的间隔排期，可以用来先验证配置对不对。
- **停用 / 启用**：停用只停止自动执行，历史轮次与对比数据都保留；重新启用时从「现在」开始计时，不会补跑停用期间的积压轮次。

### 长期对比看什么

在定时任务列表点「汇总对比」：

![长期对比视图](screenshot-longrun.png)

- **吞吐趋势图**：支持「单线」和「自定义多线」；可切换只看上行、只看下行或双向，后端线路可任意勾选组合，横轴显示测试时间；
- **跨轮汇总**：每台机器的上行 / 下行 / 丢包 / RTT / 抖动 / 重传的**均值与极值**，以及「趋势」= 后半段轮次均值相对前半段的涨跌（±3% 以内视为稳定）；至少需要 4 轮有效上下行结果，样本不足时会直接显示原因；
- **全量统计 + 窗口展示**：汇总仍统计最多 10000 轮历史；图表和逐轮明细只向浏览器发送最近 200 轮，避免长测把页面拖慢；
- **复制逐轮数据**：同时写入 HTML 表格和制表符文本，粘贴到文档保留表格排版，粘贴到 Excel / WPS / Numbers 则自动分列；
- **复制报告（含图）**：优先写入富文本 HTML，全量汇总、最近 200 轮明细和当前吞吐趋势 SVG 会一起进入剪贴板，可直接粘贴到 Word、Notion、飞书等支持富文本的位置；不支持富文本时退回 Markdown 文字。
- **长期报告排版**：新版报告改为「测试概览 → 线路表现 → 上行矩阵 → 下行矩阵 → 异常记录」，不再为每台机器重复几十行宽表。
- **记录折叠**：同一后台定时任务产生的多条测试记录会聚合为一行，展开后可逐条查看或删除；手动测试记录保持独立。
- **失败判定**：同一台机器只要上行或下行有一边没有取得有效吞吐，本轮直接记为测试失败，不进入均值、趋势和矩阵统计。

> 测试期间 Agent 正在执行长命令时，面板会把活动任务视为在线依据，避免机器实际正在测速却短暂显示「离线」。

> 跨轮对比的前提是**参数保持一致**：同一任务里参数是固定的，所以不要中途改任务的参数再拿前后数据比——需要换参数时建议新建一个任务。

## 报告

Markdown 报告包含：本次测试参数（线程 / 时长 / 端口 / TCP-UDP / ping 次数）、线路质量评价，以及每台机器的丢包率、RTT（min/avg/max/mdev）、抖动、上行、下行、重传（UDP 测试改列为 UDP 丢包与 UDP 抖动），并附每台机器的原始 ping 与 iperf3 输出。

### 线路质量评级

| 等级 | 含义 |
|---|---|
| S | 优秀 |
| A | 良好 |
| B | 一般 |
| C | 较差 |
| F | 失败 |

评级只根据丢包率、上行吞吐和下行吞吐计算。标称带宽存在时按达成率评估，未标记带宽时按绝对吞吐评估。RTT、mdev 和重传仍会展示，但只作为诊断信息，不参与等级计算，也不会因为缺失而显示“数据不足”。

只有缺少丢包或上下行结果时才显示“数据不足”；测试失败或不完整时显示“测试失败”，不会把缺失值当成 0 或评为优秀。阈值集中在 `app/quality.py` 的 `RATING_THRESHOLDS`，属于项目自定义的初始经验值，不是行业标准。结果页可展开“查看诊断详情”，报告中也有完整诊断章节。

### 测试事件与摘要

实时日志默认按预检、Ping、上行、下行、结果分析和完成阶段汇总，自动滚动与原始日志入口都保留。测试结束后结果顶部会显示成功、失败和“成功但需关注”的机器数量；需关注不等于测试失败。

报告会对地址脱敏：IPv4 只保留 A.B 两段，IPv6 保留前两组。

## 端口与安全组

### iperf3 端口什么时候是开着的

- **只在测试期间打开**：目标机的 `iperf3 -s` 由面板在开测时下发任务临时启动，**平时不监听**（Agent 只做出站心跳轮询，不会常驻 server，后端机只跑客户端）。面板日志里能看到 `[目标] 启动 iperf3 server：监听端口 …；server 存活上限 N 秒`。
- **收尾一定关闭**：正常结束、手动停止、出错中断，面板都会下发关闭任务（按 pid 文件 + 本轮用过的端口精确回收）。要看现场：目标机上 `ss -ltnp | grep iperf3`。
- **重启也会收尾**：面板在测试进行中被重启（升级 / 崩溃）时，它会把这轮起过的端口记在库里，**重启后自动回收**那台目标机上的残留 server（机器当时离线就等它上线后补做，日志里打印 `[回收] …`）。这一条是为定时任务准备的：否则残留 server 会占着端口，让下一轮直接失败。
- **异常兜底**：面板容器在测试中被重启、或目标机 Agent 掉线导致关闭任务送不到时，server 会按存活上限自过期（≈ 台数 × 2 × 单向时长 + 7 分钟，收敛到 300–3600 秒）。所以最坏情况是「短时间残留」，不会长期挂着。
- 长测（台数 × 时长很大，超过存活上限）时，server 到点后由通道内的端口预检自动重启续期，测试不会因此中断。
- **例外：发行版自带的常驻服务。** Debian / Ubuntu 装 `iperf3` 时会问一句「是否作为守护进程自动启动」，**默认是「否」**；面板自动安装时用的是非交互模式（`DEBIAN_FRONTEND=noninteractive` + `-y`），取的就是默认值「否」，装完不会留下常驻服务。但如果这台机器上**有人手工装过并回答了「是」**，就会有一个 systemd 服务一直监听 5201（命令行是 `iperf3 --server`，开机自启、被杀还会自动重启），面板既关不掉它、也没法和它共用端口。面板开测前会体检并在日志里告警，处理办法：

  ```bash
  systemctl disable --now iperf3     # 关掉并取消开机自启（推荐）
  ```

  或者在面板里把「目标机端口」改成别的端口（如 5202）绕开它。其他发行版（Fedora / RHEL、Alpine、openSUSE）的 iperf3 包都不带常驻服务。

### 但 iperf3 本身没有鉴权，所以放行范围要收紧

端口开着的那段时间里，任何能连上它的人都能自己定 `-t` / `-P` / `-R` 把目标机带宽跑满（`-R` 是目标机往外发包，云主机 / VPS 通常计出口流量），还可能把你的测速结果抢带宽搞脏。iperf3 没有内置白名单/认证，所以：

- **目标机**：放行**目标机端口**（个别后端机单独指定了连接端口时也要放行那些端口）与 ICMP，并且**只放行后端机 IP**（UDP 测试要同时限制 TCP/UDP）——这是唯一能兜住「测速窗口被扫到」的措施；
- **面板机**：放行 `.env` 里的端口；启用 HTTPS 后建议追加 `PANEL_BIND=127.0.0.1`，只保留 80/443；
- 跨公网建议套 HTTPS 反代，配置见 [deploy.md](deploy.md)。
